# Family Care 0.3.0 — 로컬 시연

팀명과 최종 앱명은 미정입니다. 현재 이름은 개발용 Family Care이며, 현재 APK는 debug 시연용입니다.

## 실행

1. 공모전 폴더의 `01_자동차켜기.cmd`로 Pleos 자동차를 켭니다.
2. `08_우리앱실행.cmd`로 최신 코드를 설치하고 앱을 엽니다.
3. `12_동승자서버켜기.cmd`를 실행하고 창을 유지합니다.
4. 차량 앱에서 **동승자** 구성을 선택한 뒤 **이동 → 이동 시작**을 누릅니다. 처음에는 속도 읽기 허용이 필요합니다.
5. **요청 → 동승자 연결 → 확인하고 시작**을 누릅니다. QR은 최대 2시간 동안 해당 역할의 접근 권한을 제공합니다.
6. 같은 PC의 브라우저에서 `http://127.0.0.1:8765/`를 열고 차량에서 복사한 연결 링크를 붙여 넣습니다. 에뮬레이터의 클립보드 공유가 꺼져 있으면 먼저 활성화하거나 휴대폰 연결 절차를 사용하세요.
7. 동승자 페이지의 **요청** 메뉴에서 ‘쉬고 싶어요’를 누릅니다. 차량의 **요청** 탭에서 **확인**을 누르면 웹에서도 **확인 완료**로 바뀝니다. 확인 버튼은 음악·공조를 자동 제어하지 않습니다.

## 새 화면 안내

- 차량은 왼쪽 메뉴로 이동합니다. `이동 → 내비`로 앱 내부 지도를 엽니다. 지도에서 목적지를 선택해 Pleos 내비로 보내거나 `차량 내비 열기`를 누릅니다.
- 동승자 웹의 하단 메뉴는 `우리 차 / 요청 / 확인 알림`입니다. 상태 확인 역할에는 요청 메뉴가 없습니다.
- 직접 입력과 장소 제안은 요청 화면의 접힌 항목을 펼쳐 사용하세요.
- 앱 안의 차량·선 그림은 직접 작성한 일러스트입니다. 0.7.0부터 실제 도로 지도는 MapLibre/OpenFreeMap으로 표시하며, 경로선·회전 안내는 기존 차량 내비에서 확인합니다. MAPS-070.txt 참조.
- 기존 약 2분 시연 영상은 0.2.0 디자인입니다. 새 UI 화면은 공모전 폴더 reference/UI-*.png에 있습니다.

## 휴대폰으로 시연

- PC용 서버 창을 Ctrl+C로 닫고 `13_휴대폰연결서버켜기.cmd`를 실행합니다.
- 목록에서 실제 PC Wi-Fi IPv4 주소를 입력합니다. PC와 휴대폰은 같은 신뢰하는 Wi-Fi에 있어야 합니다.
- Windows 방화벽 확인이 나오면 사용할 개인 네트워크 범위만 허용합니다. 스크립트는 방화벽 규칙을 바꾸지 않습니다. 공유기 포트 개방은 하지 않습니다.
- 차량 앱에서 기존 연결을 종료한 뒤 새 동승자 연결을 생성합니다. 새 QR에는 PC의 LAN 주소가 들어갑니다.
- 가족용 QR: 장소/한마디 요청·투표·상태 확인. 손님용: 한마디 요청·상태 확인. 상태 확인용: 차량 상태와 확인 알림 전용.
- 이 방식은 로컬 HTTP 시연입니다. 외부 인터넷 서비스와 실제 차량 연결에는 별도 HTTPS 서버·인증·운영 설계가 필요합니다. 이 PC 밖의 휴대폰 접속은 기기와 Wi-Fi를 연결한 뒤 별도로 확인해야 합니다.

## 2분 시연 순서

1. **동승자**: 아이와 반려동물 선택, 아이 나이 범주 선택, 추천 모드 확인. 구성 1/2 저장과 불러오기.
2. **이동**: 이동 시작. 속도 변화에 따라 가속·감속·조향 이벤트를 집계합니다. 속도 미확인 시 주행 시간과 피드백을 만들어내지 않습니다.
3. **요청**: 웹의 휴식 요청을 확인하고 장소 제안을 받습니다. 목적지는 이름·좌표 및 내비 안내 모드가 확인되어야 완료입니다.
4. **차량**: 반려동물 확인을 1분으로 시작합니다. 1분 뒤 타이머 알림이 차량과 열린 동승자 페이지에 표시됩니다. 1분 더 미확인이면 상태 확인용 페이지에서도 강조합니다.
5. **이동 종료**: 아이/반려동물이 선택되어 있으면 뒷좌석 직접 확인 알림을 띄웁니다. 확인을 누른 뒤 **기록**에서 이동 시간을 봅니다.
6. 끝나면 **차량 → 상태 확인 종료**, **요청 → 모든 동승자 연결 종료**를 누릅니다. 이동 종료와 차량 상태 확인은 별개의 기능입니다.

## 확인 기준과 한계

- 온도 30°C 이상, 배터리 20% 이하, 1/5/10/20분 타이머는 시연용 직접 확인 기준입니다. 의학적·동물복지 안전 기준이 아닙니다. 운전석 센서가 뒷좌석 환경을 보장하지 않습니다.
- 속도와 조향 변화 횟수는 시연용 임계값으로 계산합니다. 멀미 지수·운전 실력 점수가 아닙니다. 60분(0~3세 아이) 또는 90분의 실제 주행 뒤 휴식을 제안합니다.
- 현재 에뮬레이터에는 시동 OFF 신호가 없습니다. 문 열림 변화와 수동 이동 종료를 사용합니다. 재실행으로 차량 전원 OFF를 추정하지 않습니다.
- **목적지**: 좌표 기반 42dot 요청은 이름과 좌표 일치 확인. **경유지**: 이름은 반환되지만 SDK가 좌표를 0,0으로 반환하여 완료로 표시하지 않습니다. 내비 화면 직접 확인이 필요합니다.
- 목적지까지 거리·시간은 검증한 경로의 실제 응답이 있을 때만 표시합니다. 도착은 SDK 도착 이벤트가 있어야 표시하며, 실제 목적지까지 주행한 도착 시험은 남아 있습니다.
- 주행 제한이 걸리거나 제한 상태를 모르면 차량 화면의 목록·입력·QR·버튼을 숨깁니다. 재진입 시 상태를 다시 확인합니다.
- 사용자 시작 후 포그라운드 서비스로 앱이 뒤에 있어도 신호를 읽습니다. 차량 전원 OFF, 앱 강제 종료, 서버 중단 이후 작동을 보장하지 않습니다. 부팅 때 자동 재시작하지 않습니다.
- 브라우저 알림은 페이지가 열린 동안만 가능합니다. 문자, 전화, 백그라운드 웹푸시와 외부 연락처 발송은 구현했다고 주장하지 않습니다.

## 데이터와 삭제

프로필 2개와 최근 이동 기록 20개는 앱 내부 저장소에 저장합니다. 위치 경로·실명·연락처는 저장하지 않습니다. `기록 → 프로필·기록 삭제`로 지울 수 있습니다. 진행 중인 뒷좌석 확인은 유지합니다.

동승자 서버는 세션과 요청을 메모리에만 유지하고, 종료·재시작·2시간 만료 때 삭제합니다. 온도·배터리·문/창문·이동 시간·도착 정보만 공유하며 프로필과 아이 나이는 공유하지 않습니다. 15초 이상 차량 응답이 없으면 웹은 미확인으로 전환합니다. 로그에 링크나 요청 본문을 기록하지 않습니다.

## 코드와 검증

- `CareEngine.kt`: 프로필·이벤트·휴식·확인 알림 규칙, JVM 테스트.
- `VehicleSensors.kt`: 공개 차량 API capability 확인 및 읽기. 창문 값은 장치의 실제 범위를 백분율로 변환합니다.
- `NaviBridge.kt`: 한 번에 한 요청, 이벤트와 이름·좌표 확인, 25초 응답 제한.
- `RelayClient.kt`, `companion/server.py`: 역할별 연결, 요청 선점·중복 방지·재연결.
- `CareRuntime.kt`, `CareService.kt`, `CareScreen.kt`: 수명주기·로컬 기록·정차 화면.
- `companion/web/`: 외부 CDN 없이 실행되는 동승자 화면.

동승자 서버 시험: `cd companion; python -m unittest -v test_server.py`.
차량 Android 시험: `cd android; gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`.

0.4.0에서 스마트폰 길안내·케어 앱을 추가했습니다. 새 설치·연결 흐름은 `PHONE-SETUP.md`, 기능 배분은 `THREE-PRODUCTS.md`를 참고하세요.
통합 시험은 P단/정차, 서버 실행, `adb reverse tcp:8765 tcp:8765`가 필요합니다. `NavigationIntegrationTest`는 공개 SDK 예제 경로를 설정하고 끝나면 취소합니다. 사용자 주행 경로가 없는 시험용 에뮬레이터에서만 실행하세요.

`BrowserDemoTest`는 `-e browserDemo true`를 준 수동 브라우저 시연에서만 실행합니다. 기본 자동 시험에서는 건너뜁니다.
